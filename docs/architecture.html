2 · Job lifecycle

Every job ends in one of two final states

query unsupported → 422, no job
queued→ planning→ narrating→ rendering→ composing→ verifying→ succeeded
any stage, or a restart → failed · error_code · error_stage · message
Error codeMeaning
PLAN_INVALIDProvider failed 3 attempts and the curated fallback plan also failed the checks
TTS_FAILEDA sentence came back empty, silent or at an implausible speed 3 times
RENDER_FAILEDDrawing code or the video encoder failed (no retry: it is deterministic)
COMPOSE_FAILEDffmpeg could not combine video and narration after 2 attempts
QA_FAILEDThe finished MP4 failed a check; nothing is published
TIMEOUTThe job exceeded its limit; the queue moves on and the thread stops at its next checkpoint
INTERRUPTEDThe server restarted while the job was queued or running
INTERNALUnexpected exception; its message is recorded
3 · Reliability

A check at every stage

Retry what is non-deterministic. Never retry deterministic code. Verify the finished file before anyone can download it.

StageCheckOn failure
PlanningSchema; each scene's renderer accepts its steps and params; 3–40 words per sentence; 45–120 s estimate; required terms presentRetry ×2 → curated fallback plan → PLAN_INVALID
NarratingPer sentence: audio present, RMS ≥ 200, 1.5–6 words/sRetry that sentence ×2 → TTS_FAILED
RenderingDeterministic codeRENDER_FAILED
Composingffmpeg exit codeRetry ×1 → COMPOSE_FAILED
VerifyingH.264 1280×720 + AAC; duration within 0.5 s of the timeline; 5 sampled frames not blank; mean volume ≥ −40 dBQA_FAILED, never published

6 · Limits and next steps

Known limitations and the production path

Limitations today

  • No real LLM calls.
  • Rendering is CPU-bound: 90–230 s per job on an Intel MacBook.
  • A timed-out thread stops at its next checkpoint, not immediately.
  • One worker, so jobs run one at a time.
  • QA checks structure, not whether a diagram is correct; frame reviews covered that by hand.

Production path

  • An LLM provider whose JSON passes the same plan checks, with the curated plan as fallback.
  • Parallel or dedicated render workers.
  • Generation in a separate process that can be terminated.
  • A real queue with several workers, Postgres and object storage behind the existing interfaces.

Adding a STEM topic

Add one module with a TopicSpec (match patterns, required terms, reference plan) and register it. Reuse the existing scene kinds; a new visual is one renderer class. The API, worker, store and pipeline do not change.
